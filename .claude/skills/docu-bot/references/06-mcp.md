# 6단계 · 기술실 — MCP를 통한 제작 과정 효율화

목표: 매번 설정을 다시 설명하지 않고, 대화 한 곳에서 이미지 → 영상까지 반복 제작한다. 폰으로도 이어서 작업한다.

## 6-1. 내 작품을 기억하는 제작 환경
Claude 프로젝트(또는 이 스킬을 쓰는 작업 공간)에 아래를 올려 두고 "PD님 작품"으로 고정한다.
- 최종 원고(docx), 제작 바이블, 메인 인물 이미지, 공간 이미지, 무드보드 코드
- 프로젝트 지침 예: "이 프로젝트는 ○○ 다큐다. 모든 프롬프트는 바이블 vN과 첨부 원고 기준. 파일명 규칙 S##-C##-설명-v##."

새 대화 첫 요청은 **원고 파악 브리핑**으로 시작한다:
```
원고 파악 (vN · N씬 · 한글 N자 · 약 X분 X초)
구조: 기(S#) → 승(S#) → 전(S#) → 결(S#)
이 콘텐츠의 핵심(내가 보는 세 가지): 1… 2… 3…
시작 전에 정리할 것: ① 원고와 자료의 충돌(시대·기계·장소) ② 이미지 자산의 확정 여부
```
충돌(예: 원고는 1950년인데 자료 사진은 1951년 기계)은 반드시 먼저 짚고, 선택지와 추천을 준다.

## 6-2. MCP로 이미지 → 영상 반복 제작
Higgsfield 같은 생성 플랫폼을 MCP 커넥터로 연결하면 대화에서 바로 생성한다.
(Nano Banana 등으로 이미지 → Seedance/Kling으로 영상)

반복 루프:
1. 컷 선택 → 바이블 고정값 + 3·4단계 프롬프트로 생성 요청 (모델, 비율 16:9, 길이, 오디오 여부, 레퍼런스 이미지 명시)
2. 결과마다 **작업 기록**을 남긴다:
   ```
   S04-문답시연-02 / job 아이디 (Seedance · 12초 · 스타트=튜링 타자 · 엔드=105621 인서트)
   구성: 0-3s … / 결과: 좋은 점, 문제점 / 다음: 무엇을 바꿀지
   ```
3. 사용자가 "7, 9, 12번 다시"처럼 번호로 지시하면 해당 컷만 바꿀 점 하나씩 반영해 재생성한다.
4. 렌더 전 **사전검사**: 바이블과 의상·시대·조명 불일치, 금지어(배우 이름), 크레딧 소모량을 확인하고 말한다.

연결된 생성 도구가 없으면 같은 형식의 프롬프트와 작업 기록표만 만들어 주고, 사용자가 붙여 넣어 쓰게 한다.

## 6-3. 핸드폰으로 완성하는 작업 환경
- Claude 앱(모바일)에서 같은 프로젝트를 열면 원고·바이블·커넥터가 그대로 이어진다.
- 폰에서는 "S06 다시, 카메라만 더 느리게"처럼 짧게 지시하고, 결과 확인·다운로드·재생성만 한다.
- 긴 대본 수정과 편집(8단계)은 PC에서 한다.

## 출력
환경 세팅 체크리스트(올릴 파일, 프로젝트 지침 초안, 연결할 커넥터) + 컷별 작업 기록표.
